### Project details ###

This was created in 3 days in part of trying to get a better understanding of other approaches to web development, I really enjoyed my time trying to figure out and grasp and understanding of how elixir/pheonix works, and while I do appreciate the solutions it provides to long-term standing issues with web development, I don't think it will really apply to real-world use cases of complex and intricate websites, while it does shine in static data display and performance, it is not a viable solution for modern applications that require constant user feedback and as such, an app that responds.

And the performace enhancements it does bring to the table make me think, do I really need this performance if 95% of devices on the planet can run builds of React/Angular/Vue or even plain HTML (which is getting better at being independent solution day by day), and would developers really invest their time learning a framework that is limited by design?

Thank you for coming to my TED talk

### Project Setup

- Make sure you have elixir properly installed before running the Pheonix server

To start your Phoenix server:

- Run `mix setup` to install and setup dependencies
- Start Phoenix endpoint with `mix phx.server` or inside IEx with `iex -S mix phx.server`
- IMPORTANT: IF RUNNING LOCALLY, YOU NEED TO INCLUDE A openweathermap.org API KEY IN THE `.env` FILE TO VIEW `/weather <city>` FUNCTIONALITY 

Now you can visit [`localhost:4000`](http://localhost:4000) from your browser,
OR
Alternitively you can visit the (hopefully) hosted version [here](https://pheonix-liveview-local-messager.gigalixirapp.com)
